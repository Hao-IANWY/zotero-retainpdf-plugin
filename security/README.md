# 安全职责与验证

本目录管理项目级安全规范和检查导航，不集中搬移业务安全实现。

- HTTP 鉴权与请求校验由 `backend/api` 的入口负责。
- 模型凭据、运行时配置和网络访问限制由对应后端服务负责。
- 安全单元测试跟随实现，跨服务安全场景归项目级测试。
- 不提交 API token、密码、真实数据库、用户 PDF 或未经脱敏的模型请求。
- 调整权限、凭据或网络边界时，同步更新模块测试与架构说明；目录迁移不
  改变现有安全策略或环境变量优先级。

## 浏览器访问边界（2026-10 起）

- `X-API-Key` 是服务间/脚本调用的白名单密钥。匿名模式（不配置 key）只表示
  「不做 API key 校验」，不表示「任意网页可以驱动本服务」。
- 浏览器来源由 `auth::origin_gate` 单独把守：带 `Origin` 且与本服务 `Host`
  不一致、又不在 `RUST_API_ALLOWED_ORIGINS` 白名单里的请求一律 403。
  不带 Origin 的客户端（Zotero 插件、脚本、pipeline worker）不受影响。
- 反代在请求上注入的 `X-API-Key`（如 `proxy_set_header X-API-Key ...`）
  属于服务端基础设施信任链的一部分：它证明请求经过了你的反代，不证明
  浏览器访客身份。公网部署的访客边界由边缘认证（如 Cloudflare Access）
  与反代自身的访问控制承担。
- 门禁只信 `Host` 判同源，不信 `X-Forwarded-Host`——后者不在浏览器
  禁止伪造的头名单里。改写了 `Host` 的自备反代需配置白名单。

目录归属参阅[仓库目录职责](../docs/core/repository-layout.md)。有实际的独立
检查工具后再建立 `checks/`，不预建空目录，也不复制已有鉴权逻辑。
