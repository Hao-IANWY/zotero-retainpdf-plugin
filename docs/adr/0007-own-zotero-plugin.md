# 0007 自研 Zotero 插件

> 状态：已采纳（2026-10-11）。**取代同日路线 B（协议模拟）**，原规划见
> [zotero-pdf2zh-protocol-emulation.md](../ops/planning/zotero-pdf2zh-protocol-emulation.md)。
> 执行未开始，里程碑与部署形态规划将建于 ops/planning/。

## 1. 背景

文献翻译的主场景在 Zotero：库内管理 PDF，期望"右键附件 → 整篇排版保留翻译
→ 双语 PDF 自动挂回条目"。生态里 guaguastandup/zotero-pdf2zh 已实现这条
链路的全部 UI，当天先评估两条路线并选择 B（服务端模拟 pdf2zh server 协议、
复用上游插件、零插件开发）；同日复核后推翻，原因：

1. 逆向契约无正式 spec，上游任何协议小改即断，长期维护成本不可控；
2. 与 [0006](./0006-remove-ai-chat.md) 的"简洁服务端"方向叠加后，自有插件
   对原生 API 的掌控价值显著高于省下的插件开发量；
3. 插件的 UX 控制权（菜单、进度、产物挂载语义）比省事更重要。

## 2. 决策

自研 Zotero 插件（TypeScript，基于 zotero-plugin-template，目标 Zotero 7），
作为 `/api/v1` 的第一方客户端：原生契约，不建协议兼容层。访问鉴权后改为可选
（凭证前置，见 ADR 0009）。

**兼容范围修订（2026-10-12）**："目标 Zotero 7"放宽为 **Zotero 7+**。manifest 的
版本闸门定为 `strict_min_version: "6.999"` + `strict_max_version: "*"`：模板默认
`"8.*"` 在 Zotero 10 拒装；而 Zotero 10（官方开发者文档 + zotero-client 测试夹具
双重确认）把**不写上限**视为未适配、同样拒装，且写死具体大版本（如 `"10.0.*"`）
会在下个大版本重演拒装——通配 `"*"` 是 Zotero 官方测试插件的写法，兼容问题改由
真实 API 报告驱动修复。

**仓库形态修订（2026-10-12）**：原决策为独立仓库；同日在"服务端整体开源"
（ADR 0008）的前提下改为**单仓库**——插件收进本仓库 `plugin/`，形态对标
guaguastandup/zotero-pdf2zh（插件 + server 同仓发布）。独立仓库的两条硬理由
（许可证边界、私有仓库装不下公开发布通道）随开源决策消解，单仓库另获
跨端原子提交之利。独立仓库的插件历史就此归档（未推送远端）。

关键约束：

- **许可证（2026-10-12 修正）**：M0 落地时核实底座 zotero-plugin-template 为
  AGPL-3.0（立项时误记为 MIT），插件因此按 **AGPL-3.0-or-later 开源发布**——
  即本 ADR 替代方案中预留的"含上游 AGPL 代码则开源"分支。对 zotero-pdf2zh
  本身仍守 clean-room（读行为不抄代码）；插件与服务端是经 HTTP 通信的独立程序，
  服务端"私有部署不分发"结论不变。
- 插件职责：右键附件 → 读文件 → 上传建任务 → 事件/轮询进度 → 下载产物 →
  挂回条目子附件。
- 远程部署受公网入口约束：Cloudflare Access（OTP）挡机器客户端，
  v1 限定内网 / VPN 直连；公网方案（Access Service Token / 独立 API 域名）
  在 M4 评估。

## 3. 后果

- 获得完整 UX 控制权与原生契约，摆脱逆向协议的前向兼容负担。
- 新增插件自身的开发与 Zotero 版本兼容维护面、xpi 分发义务
  （GitHub Release + updates.json）。
- 服务端许可证结论不变：私有部署不分发，AGPL 义务不触发。
- 里程碑：M0 脚手架 → M1 单文件 MVP → M2 体验对齐 → M3 批量与配置 →
  M4 分发与公网形态，施工图将建于 ops/planning/。

## 4. 替代方案

- **路线 B：服务端协议模拟（同日先选后弃）**——改造面小、无插件分发义务，
  但契约逆向脆弱、UX 受上游插件限制；其规划文档保留，§3 契约逆向成果
  转为自有插件的 UX 参考。
- **fork 上游插件改造**——立即引入 AGPL 衍生义务（插件必须开源），
  且背上上游代码结构的理解成本，否决。
