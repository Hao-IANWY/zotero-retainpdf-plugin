# 认证与错误

## 认证

**鉴权是可选的**：服务端未配置任何访问密钥（`RUST_API_KEYS` / `auth.local.json`）时
进入开放模式，所有接口匿名可用；配置了密钥则除 `GET /health` 外全部要求请求头：

```http
X-API-Key: your-api-key
```

认证失败通常返回 `401` 或 `403`。开放/上锁由部署方决定（ADR 0009）：本地与受网关
保护的远程部署通常开放，公网裸奔部署建议上锁。

## 凭据字段

任务请求里可能包含下游 provider 凭据，例如：

- `ocr.mineru_token`
- `ocr.paddle_token`
- `translation.api_key`
- command provider 的 `ocr.options.credential`

后端响应不会回显这些明文。前端只能通过类似 `*_configured` 的布尔字段判断是否已配置。

## 错误处理原则

- HTTP status 表示请求级错误，例如认证失败、参数非法、资源不存在。
- job 的 `status=failed` 表示任务运行失败。
- 任务失败原因优先读 `failure` 或 diagnostics 接口，不要从 `stage_detail` 反推。

常用状态：

- `400`: 请求参数不合法。
- `401`: 缺少或错误的 API key。
- `404`: job 或 artifact 不存在。
- `409`: 当前状态不允许该操作。
- `500`: 后端内部错误。
